Competitive read · 16 Aug 2026

PiOcarina against the field

Three tools are worth measuring against. Claude Code and Codex are engines that grew harnesses around themselves. T3 Code is the direct structural peer: a harness with no engine of its own, wrapping other people's agents. PiOcarina is the same shape as T3 Code — a control surface over one engine, pi — and competes with it on the axis T3 Code has left empty: the keyboard. The gaps that matter are not in the shell. They are in what happens to the code after the agent writes it.

01Who is who

Shape first. Feature counts mean nothing until you know what each thing is trying to be.

Claude Code

Engine + harness · Anthropic

Terminal, VS Code, JetBrains, desktop, web, mobile — one engine behind every surface. Hooks, skills, subagents, MCP, sandboxing, scheduling, CI. Sessions move between surfaces mid-task.

Codex

Engine + harness · OpenAI

Rust CLI plus desktop, IDE, cloud and Chrome. OS-level sandbox (Seatbelt / Landlock), three approval policies, AGENTS.md, hooks, skills, subagents, worktree isolation, conversation forking.

T3 Code

Harness only · pingdotgg

Open-source control plane over Claude Code, Codex, Cursor, OpenCode and Grok. Three panels, git worktrees, one-button PR, turn-by-turn diff viewer, embedded terminal, desktop + web + mobile. Explicitly very early.

PiOcarina

Harness only · this repo

Keyboard-first Electron shell over pi. Tiling thread strip, vim modal keys, block-level transcript navigation, leap, tool ledger, checkpoints, approvals, pty column, git commit card.

04What the matrix actually says

Three readings, in the order they should change what gets built.

The shell is finished; the loop is not

Diagnosis

Every competitor closes the circle: agent writes → you read the diff → you commit → you open a PR. PiOcarina stops at "agent writes". The commit card knows which files changed and by how many lines, but there is nowhere to read the change. That single gap is worth more than the next ten.

Nothing is plugged in

Diagnosis

MCP, hooks, user-defined commands, plan mode: zero. All four are table stakes in the other three tools. Some of this is pi's to provide, but the harness currently cannot even show what pi has.

The keyboard is a genuine moat

Advantage

T3 Code — the only direct peer — ships plain mod+key bindings and a command palette. No modal model, no leader chords, no block navigation, no leap. Nobody else is building this. It is the one axis where PiOcarina is not catching up.

05Build order

The owner defers MCP and plan mode. Both leave the ranking and go to the bottom.

  1. Diff viewercore

    Show the change the agent made. One diff for each turn. Move through hunks with j and k. Stage or revert one hunk with a.

    All three other tools have this. PiOcarina has none of it. The commit card counts the changed lines, but you cannot read them. A diff also suits block navigation better than it suits a mouse.

  2. Worktree for each threadcore

    A thread opens its own git worktree. Two threads then edit two different working copies.

    The strip holds many threads at once. They all share one working copy today, so two running threads corrupt each other's edits. This makes the existing layout safe.

  3. Push and open a pull requesthigh

    Add one action to the commit card. It commits, pushes the branch, and opens the pull request page.

    The commit card already does the first step. This finishes the path from prompt to review, which is where the other tools end and PiOcarina stops.

  4. Finish the ask tool and subagentshigh

    Build the two tools behind the cards that the app already draws.

    The app shows an ask card and nested subagent rows. Neither tool exists. A drawn card for a missing feature is worse than no card.

  5. Project commands and the instruction filehigh

    Read the commands the project defines. Show them in the slash menu. Show the instruction file the agent reads.

    The slash menu has three fixed entries. Every other tool lets the project add its own. You also cannot see which instruction file pi loaded.

  6. Fork a threadmedium

    Copy a thread at a checkpoint. Try two answers to the same question.

    Checkpoint restore already exists and does the hard part. Forking adds the second branch instead of replacing the first.

  7. Rebindable keysmedium

    Let the user change any key. Keep the current keys as the default.

    The keys are correct for one person today. A second user needs to change them.

  8. Hookslow

    Run a shell command when a turn starts, when a turn ends, or after an edit.

    Useful for a formatter or a test run. Nothing else waits for it.

  9. Sandbox and permission ruleslow

    Write allow rules and deny rules inside the app. Run agent commands in an operating system sandbox.

    The app enforces approvals now, but you cannot author the policy in it. This matters when the agent runs without a person watching. PiOcarina does not do that yet.

  10. MCP surfacedeferred

    List MCP servers and their tools. Show MCP tool calls in the ledger.

    Deferred by the owner: not part of this workflow. Reopen this if pi ships skills or tools that only arrive over MCP.

  11. Plan modedeferred

    The agent proposes a plan. You approve the plan before the agent edits any file.

    Deferred by the owner: not part of this workflow. The approve card and the block menu already exist, so the cost stays low if you want it later.

06Not worth chasing

Stay out

Brief non-goals, and still right
  • Multi-provider support. T3 Code's reason to exist. PiOcarina's is being the best surface for one engine — those two goals pull apart.
  • Web, mobile, cloud. A keyboard-first tiling shell does not survive the trip to a phone.
  • IDE extension. The whole premise is that the shell is the surface.
  • CI and headless. That is pi's job; the harness would only be in the way.

Watch

Could change the calculus
  • T3 Code adding a modal keyboard layer. The only competitor positioned to take the moat.
  • pi gaining native subagents or elicitation. Two of our specs stop being ours to build.
  • MCP as the way skills and tools ship. Raises the cost of not having a surface for it.
