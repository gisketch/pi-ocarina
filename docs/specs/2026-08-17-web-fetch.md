# Web fetch: the agent reads a page as an article, not as tag soup

Status: **APPROVED 2026-08-18.** Grilled 2026-08-18. Tickets in
[2026-08-18-web-fetch.md](../exec-plans/active/2026-08-18-web-fetch.md).

## Problem

The agent has no way to read a URL. When a task points at documentation, an
issue, or an API reference, it shells out to `curl` and receives raw HTML —
navigation, scripts, and somewhere inside it the paragraph it wanted, at many
times the token cost.

## Desired outcome

A `fetch` tool. The agent gives a URL and reads prose. The reader sees a compact
row — method, host, status, size — and expands it to exactly what the agent
received.

## Settled decisions

### 1. Our own tool, and no new dependency

Node 22 ships `fetch` globally in the main process, so the transport is free.

The extraction is ours too. `@mozilla/readability` needs `jsdom`, which is 21
packages, to strip tags inside an Electron bundle. What we actually need — drop
`script`, `style`, `nav`, `header`, `footer`, `aside`; pick the densest content
element; emit Markdown for headings, paragraphs, lists, links, code and quotes —
is about two hundred lines and is exactly the kind of thing this repository
already owns four of (`markdown-block`, `markdown-inline`, `markdown-segments`,
`highlight`). It is fixture-testable, which a third-party heuristic is not.

Markdown out means the existing renderer draws the body with no new path.

### 2. GET and HEAD run; everything else asks

`POST`, `PUT`, `PATCH` and `DELETE` change something on someone else's server.
That is an outward, often irreversible action, and this app already has one
place where the user says yes or no to those: the approval gate. A non-GET fetch
goes through it, with the method, the URL and the body shown.

No second consent mechanism gets invented for this.

### 3. Caps stated, never silent

30 second timeout. 100 KB read cap, applied to the response body before
conversion. A truncated page says so, with the size it stopped at. A cap the
reader cannot see is indistinguishable from a page that was simply short.

### 4. No credentials, ever

No cookies, no stored authorization, no credential headers — not from us and not
from the model. A page that needs a login fails honestly and says so. The agent
is not given a way to authenticate to a third party on the user's behalf.

### 5. Fetched content is data

A page can contain text addressed to the model. The tool's guidelines say
plainly that page content is information to read, never instructions to follow.
The result is labelled with its source URL so the boundary is visible in the
transcript too.

### 6. Local addresses are allowed, and named

A developer's own `localhost:3000` is a legitimate target, and the agent already
has `bash`, so blocking it protects nothing. The row always names the host, so a
local fetch is visible as one.

## In scope

- The `fetch` tool: URL in, Markdown out for HTML; the body verbatim for JSON,
  text and Markdown.
- Our HTML-to-Markdown extractor, with a stripped-text fallback when the page
  has no recognisable content element.
- A `fetch` ledger row: `GET example.com/docs · 200 · 12.3KB`, expanding to the
  converted body.
- Failures — timeout, 4xx, 5xx, oversize, unreadable — as failed rows carrying
  the status.
- Non-GET methods through the approval gate.

## Out of scope

- A browser. No JavaScript, no login, no screenshots.
- Crawling. One URL per call.
- A search tool.
- Downloading binaries to disk. A binary response reports its type and size and
  is not converted.

## Acceptance behavior

- "Read the docs at <url>" produces a `fetch` row and an answer grounded in the
  page, with no `curl` in the ledger.
- An HTML page arrives as Markdown; a JSON endpoint arrives as JSON.
- A page over the cap says it was truncated and at what size.
- A timeout or a 500 renders as a failed row naming the status.
- A `POST` raises an approval card naming the method and URL; refusing it
  returns a denied row.
- A binary response is not converted and says what it was.

## Constraints

- Fetching happens in main. The renderer never fetches.
- The cap is enforced while reading, not after: a 2 GB response must not be
  buffered to discover it was too big.
- Redirects are followed within the same request, to a bounded depth, and the
  final URL is what the row reports.

## Validation

- Unit: extraction over HTML fixtures — an article page, a page with no article
  element, a page that is only navigation, entities, nested lists, code blocks.
- Unit: the cap, the timeout, the method gate, and each failure shape.
- A live pass: the agent reads a real documentation page and answers from it.
