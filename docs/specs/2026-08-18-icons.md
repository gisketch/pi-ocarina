# Real icons

Status: **Approved 2026-08-18.** Owner decision: **Codicons for the chrome,
Phosphor (light) as fallback.** Mockup: `docs/reference/design/PiOcarina
Polish.dc.html`, section 06. Tickets in
[2026-08-18-icons.md](../exec-plans/active/2026-08-18-icons.md).

## Problem

Every mark in the UI is a unicode glyph: `■ □ ▸ ▾ ✓ ✗ × · ↗ …` scattered as
string literals through components. Glyph coverage and metrics differ by
platform font, weights do not match each other, nothing aligns to a common
grid, and there is no vocabulary — the same concept can be drawn with
different characters in two places and nobody notices. The design wants a
terminal, nerd-font feel; actual nerd-font glyphs via system fonts are the
least reliable way to get it.

## Desired outcome

One icon system: a real SVG icon set, one size and stroke discipline, themed
by `currentColor`, imported per-icon so the bundle carries only what is used.
Unicode survives only where it is text, not iconography (the `·` separator,
ellipsis).

## Candidates

Surveyed for the grill. All render inline SVG, tree-shake, and color via
`currentColor`.

1. **Lucide** (`@lucide/svelte`) — ~1,600 icons, single stroke style,
   consistent 24-grid, the most active successor to Feather. First-class
   Svelte 5 package. The safe modern default; feel is "clean product UI"
   more than "terminal".
2. **VS Code Codicons** (`@vscode/codicons`, or via Iconify as `codicon:*`)
   — ~600 icons designed for editor chrome at 16px. **This is the
   nerd-font feel by construction: Nerd Fonts literally embed codicons.**
   Smaller set; no first-party Svelte package, so it rides on unplugin-icons.
3. **Tabler Icons** (`@tabler/icons-svelte`) — 5,900+ stroke icons, huge
   coverage, slightly rounder personality. Heaviest package churn.
4. **Phosphor** (`phosphor-svelte`) — ~1,500 icons in six weights;  the
   thin/light weights suit a muted terminal aesthetic well.
5. **unplugin-icons + Iconify** — not a set but a compiler: any Iconify set
   (codicon, lucide, tabler, octicon…) becomes a Svelte component at build
   time, zero runtime dependency. Allows codicon-first with lucide filling
   gaps — at the cost of a build-plugin dependency and a two-set vocabulary
   to police.

**Decided 2026-08-18 (owner): Codicons first, Phosphor light fallback.**
Codicons for the chrome — statusbar, tool labels, git — it is the VS Code
terminal vocabulary, the sharpest nerd-font match, and every symbol in use
(branch, diff, terminal, symbol kinds for lsp rows) exists there. Phosphor at
light weight (1.5px stroke) where Codicons runs out: files, media, arrows,
misc. The rule for reaching into Phosphor: only when Codicons has no icon
for the concept, recorded in the icon seam's registry.

## In scope

- Choosing the set (or set + fallback) and the delivery mechanism.
- An inventory of every glyph-as-icon in the renderer and its replacement.
- One Icon seam: size, stroke width, optical alignment against the mono grid.
- Statusbar, ledger gutters, chips, overlays, composer marks.

## Out of scope

- Recoloring or redesigning any surface — same places, better marks.
- App icon, dock icon, tray.
- Animated icons.

## Acceptance behavior

- No component renders a unicode character as an icon; the inventory is zero
  except the documented text-glyph exceptions.
- Icons align on the text baseline grid at ledger row height without vertical
  wobble, in both themes.
- The bundle grows by only the icons used — measured, stated in the review.
- Every icon renders identically on macOS, Windows, Linux builds.

## Constraints

- Renderer-only. No network fonts, no icon font files — inline SVG only, per
  the app's no-remote-asset posture.
- `currentColor` throughout; an icon never carries its own palette.
- The 350-line file discipline applies to the inventory work as much as any
  code: replacement lands surface by surface, not as one sweep commit.

## Validation

- A greppable check: no icon-class unicode literals in components.
- Browser screenshots of statusbar, ledger, chips at 1x and 2x, both themes.
- Bundle-size delta recorded in the plan doc.

## Decisions

1. **Sets**: Codicons primary (chrome), Phosphor light fallback — owner
   decision above. A third pack, `simple-icons` (CC0), carries the language
   marks a row wears when it names a language server: neither Codicons nor
   Phosphor has brand icons, and `lsp` on all six tools was true and told a
   reader nothing the file beside it did not. C# has no mark of its own there
   — Microsoft's trademark policy took it out — so a C# row wears .NET's.
2. **Gutter status nodes stay squares**: the `■` pulse nodes are design
   language (the Polish mockup still draws them as colored squares), not
   iconography. Chevrons (`▸`/`▾`) become icons.
3. **One `<Icon>` seam**: a single wrapper owns size and optical alignment;
   components name icons from a registry, never import a pack directly — the
   registry is where the Codicons-before-Phosphor rule is enforced and
   visible.

## Open questions (small, settle in implementation)

- Exact pixel size against the mono grid (14px in a 20px row vs em-derived) —
  measure in the browser, record in the plan doc.
- The final list of unicode that stays as text (`·`, `…`, and whether `↗`
  survives) — recorded as the registry's documented exceptions.
