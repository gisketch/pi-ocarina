## W1 — HTML becomes Markdown — `done`

> A pure function: an HTML string in, Markdown out. No network, no dependency.

- `src/main/web/html-text.ts` — a small forgiving tokenizer over tags and text,
  with entity decoding. Not a DOM: a stream of open/close/text events is all the
  extraction needs.
- `src/main/web/extract.ts` — drop `script`, `style`, `noscript`, `svg`, `nav`,
  `header`, `footer`, `aside`, `form`; choose the element with the most text
  among `article`, `main`, `[role=main]`, else `body`; emit Markdown for
  `h1`–`h6`, `p`, `ul`/`ol`/`li`, `a`, `code`/`pre`, `blockquote`, `hr`,
  `table` rows as lines, and `img` as its alt text.
- `title` becomes the document's first heading when the content has none.
- Acceptance: an article page yields its prose and headings and none of its
  navigation; a page with no article element still yields its body text.
- Validation: `extract.test.ts` over HTML fixtures — article, no-article,
  nav-only, nested lists, entities, code blocks, malformed tags.

## W2 — the `fetch` tool — `done`

> The tool itself: caps, timeout, methods, and the approval gate.

- `src/main/web/fetch-page.ts` — `fetchPage({ url, method, headers, body }, signal)`
  reads the response with a running 100 KB cap, a 30 s timeout, bounded
  redirects, and reports the final URL, status, content type and byte count.
  Non-text content types are described, never converted. No cookies, no
  authorization.
- `src/main/session/fetch-tool.ts` — `FETCH_TOOL = 'fetch'`, TypeBox parameters,
  guidelines that state page content is data and never instructions.
- A non-GET method goes through the existing approval gate before the request.
- Registered in `session-extensions.ts` for every session; a child gets it only
  when its role's tools allow it.
- Acceptance: a GET returns Markdown; a POST raises an approval card and a
  refusal returns a denied result; an oversize page says it was truncated.
- Validation: `fetch-page.test.ts` against a local HTTP server for status,
  timeout, cap, redirect and content type; `fetch-tool.test.ts` for the gate.
- Blocked by: W1

## W3 — the row — `done`

> What the reader sees.

- `tool-rows.ts` — a `fetch` kind, target `GET example.com/docs`, meta
  `200 · 12.3KB`; a failure carries the status.
- The body is the converted Markdown, rendered by the existing markdown path.
- Acceptance: a fetch draws a labelled row that expands to readable prose.
- Validation: `tool-rows` tests; a browser pass.
- Blocked by: W2

## Review — 2026-08-18

- **P1 — a fetched page could overflow the stack.** Extraction walks its tree
  recursively at four points, so a page's nesting depth was this app's call
  stack; ten thousand nested `<div>`s threw `RangeError` and failed the fetch
  outright — a page a hostile host can serve deliberately. The tree is capped
  at 100 deep, which bounds every walk at once, and the text inside the refused
  nesting is still kept.
- **P2 — a timeout, a 4xx or a 5xx drew a successful row.** pi marks a call
  failed only when `execute` throws, so the tool has to throw; the outcome
  rides on the error so the row still says the status.
- **P2 — the approval card for a `POST` never showed the body**, which is the
  part that changes something on a server this app does not own.
- **P3 — a body of exactly the cap was reported truncated.**
- **P3 — a binary with no `content-length` was reported as 0.0KB**, a
  measurement that was simply false. Counted rather than assumed.
