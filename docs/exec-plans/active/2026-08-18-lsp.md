## L1 — an LSP client that speaks to a real server — `todo`

> One `LspClient`: spawn a command, hand its stdio to `vscode-jsonrpc`,
> `initialize`, and expose the five requests the tools need. Nothing about
> pools, workspaces or pi.

- `src/main/lsp/client.ts` — `startClient(spec, root)` returns a client with
  `documentSymbol`, `definition`, `references`, `hover`, `rename`, plus
  `diagnostics(path)` fed by the `textDocument/publishDiagnostics` notification,
  `didOpen`/`didClose`, and `stop()`.
- Documents are opened before a positional request and closed after; an LRU cap
  of 100 keeps a long session from holding every file open.
- Acceptance: against a fake server, `initialize` completes, a `documentSymbol`
  round-trips, and a published diagnostic is readable.
- Validation: `client.test.ts` drives a fake language server over a real pipe,
  so the framing is exercised rather than mocked.
- Blocked by: adding `vscode-jsonrpc` to dependencies.

## L2 — the server table and what a workspace can run — `todo`

> Which servers exist, which languages they cover, which one a file routes to,
> and which are plausible for this workspace.

- `src/shared/lsp.ts` — `LspServerSpec`, `SHIPPED_SERVERS` (typescript, svelte,
  python, go, rust, csharp, json), `serverForPath`, `LspServerState`.
- `src/main/lsp/detect.ts` — `detectServers(cwd)`: a server is *plausible* when
  one of its `rootFiles` exists, and `ready` when its binary resolves on PATH.
- Acceptance: a repo with `tsconfig.json` and a `.csproj` reports both, each
  marked ready or missing; `serverForPath('a.razor')` finds none.
- Validation: `lsp.test.ts` for routing, `detect.test.ts` over fixture trees.

## L3 — a pool that starts late and lets go — `todo`

> Lazy start per language, reference counting, idle reaping, one retry.

- `src/main/lsp/pool.ts` — `LspPool` keyed by `${root}:${serverId}`.
  `withClient(path, work)` starts on demand, increments in, decrements in a
  `finally`, and reaps at zero references after 5 minutes idle.
- A transport error evicts the client and retries once when the call is marked
  read-only; a mutating call never retries.
- `running()` reports what the status bar shows.
- Acceptance: two calls to the same language share one process; a killed server
  is replaced on the next read; an idle server stops.
- Validation: `pool.test.ts` with an injected clock and a stub client factory.
- Blocked by: L1, L2

## L4 — six tools the model can actually aim — `todo`

> `lsp_diagnostics`, `lsp_definition`, `lsp_references`, `lsp_symbols`,
> `lsp_hover`, `lsp_rename_preview`. Addressed by symbol name, not by column.

- `src/main/lsp/tools.ts` + `src/main/lsp/locate.ts` — `locate(client, path,
  symbol)` resolves a name to a position through `documentSymbol`; an ambiguous
  name returns candidates instead of guessing.
- Results are compact text: `path:line  kind  name` lines, capped.
- Acceptance: asking for references to a symbol returns its call sites; an
  unknown symbol says so and lists what the file does contain.
- Validation: `tools.test.ts` against a stub client; `locate.test.ts` for
  exact, ambiguous and missing names.
- Blocked by: L3

## L5 — workspace settings, stored — `todo`

> The switch and the per-server choices, on the workspace record.

- `src/shared/vocabulary.ts` — `WorkspaceLsp { on: boolean; servers: Record<string, boolean> }`
  on the workspace.
- `src/shared/commands.ts` — `workspaceSettings` (read) and `setWorkspaceLsp`.
- `src/main/catalog.ts` — persisted with the rest of the workspace record;
  absent means off.
- Acceptance: turning LSP on for a workspace survives a restart and does not
  touch any other workspace.
- Validation: `catalog` round-trip test; a migration test for a record written
  before this field existed.

## L6 — the Workspace Settings overlay — `todo`

> A second settings surface, scoped to the open workspace, reachable from the
> global one and from the status bar chip.

- `src/renderer/src/components/overlays/WorkspaceOverlay.svelte` — names the
  workspace, an LSP switch, then one row per plausible server: label, state, and
  for a missing one the install command with `y` to copy.
- Keys match `SettingsOverlay`: `j`/`k` move, `⏎` toggles, `esc` closes.
- Settings gains a `workspace settings` row; `keyboard.ts` gains the overlay.
- Acceptance: a workspace with a `tsconfig.json` lists TypeScript as ready or
  missing; toggling the switch persists; copying an install line does not run it.
- Validation: overlay state tests; a visual pass beside `SettingsOverlay`.
- Blocked by: L5

## L7 — the session actually uses it — `todo`

> Registration, demotion, the system prompt line, and diagnostics on edit.

- `src/main/session/lsp-extension.ts` — registers the six tools when the
  workspace has LSP on, and subscribes `tool_result` to append a changed file's
  errors (10 lines, errors only) when a server for it is already running.
- `session-factory.ts` — when LSP is on, `grep` and `find` are rebound with a
  description naming them a fallback.
- `session-extensions.ts` — a system prompt line listing the live languages.
- Acceptance: with LSP on, an edit that breaks the build carries the error back;
  grep's description says it is a fallback; with LSP off nothing changes.
- Validation: `lsp-extension.test.ts` for the injection and the cap;
  `session-factory.test.ts` for the demotion, both states.
- Blocked by: L4, L5
